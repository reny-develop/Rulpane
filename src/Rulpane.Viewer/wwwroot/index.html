How to write a simple system as one Rulpane link

Rulpane (https://reny-develop.github.io/Rulpane/) turns one link into a working screen: a request and its approval, a checklist, a sign-off, a loan register, a booking, a roster. The link carries everything — the rules, the layout, the look and where things stand — so there is no server, no sign-up and nothing to install. Whoever opens the link uses the system, every step rewrites the link, and sending the new link on hands over the system as it stands.

This page is everything needed to write one. It is meant to be read by a person or by an AI.

If you are an AI asked to make a Rulpane link

  1. Work out what can be done in the system, by whom, and when it is finished.
  2. Write one paneset (below): a JSON document with the rules in r, the screen in v and, if it helps, where to start in s. Start from the complete example in A whole paneset and change it; do not invent keys or operations that are not on this page.
  3. Give the person the link: https://reny-develop.github.io/Rulpane/#p= followed by the paneset as JSON on one line, with every space written as %20 — inside strings too, such as "Mon%20am", or a chat cuts the link at the first one. Nothing else needs encoding; other languages' characters may stay as they are.
  4. Also give the JSON itself in a code block, and say: if the link does not open, paste the JSON into the editor at https://reny-develop.github.io/Rulpane/#make, press "Make link", and tell me the reason it shows. The reason names the key that is wrong.
  5. Before answering, check the paneset against Before you answer.
  6. Say plainly what Rulpane cannot do (see What a link cannot do), when the request needs it: anybody holding the link can take any step, and nothing is hidden from them.

The link

https://reny-develop.github.io/Rulpane/#p=<paneset>

<paneset> is either the JSON of a paneset, on one line, or the name of one. The keys of a paneset can also be given one by one, #r=…&v=…&t=…&s=…&b=…; each takes a name or a JSON document the same way, and one given in the link goes over the paneset's own: #p=expense-claim&t=paper is that paneset in another theme. A JSON value runs to its own end, so any &, # or = inside its strings is fine. Write a literal % in a string as %25.

Once the link is opened, every step rewrites it into a shorter packed form (z: followed by deflated base64url). That form is for the page; never write it by hand.

A paneset

{
  "$schema": "rulpane/paneset/v1",   // required
  "r": …,   // the rules: a rule set document, or the name of one — required
  "v": …,   // the view: what the screen shows, and where — optional
  "t": …,   // the theme: colours, corners, type, spacing — optional
  "s": …,   // where to start: the state's data — optional; the rules' own start without it
  "b": …    // which of the rules' names the view reads under other names — optional
}

The paneset, a view and a theme each must carry their $schema (rulpane/paneset/v1, rulealize/view/v1, rulealize/theme/v1); one without it is refused. A rule set's $schema is only a label. Each of r, v and t is the document written in place, or a name:

Key Names that exist
r bundled: approval, checklist, request, roster, signatures; from the Rulealize Registry as <id>@<x.y.z>, such as Rulealize.RuleSet.Request@1.1.0
v bundled: approval, progress, roster, stages; from the Gallery as <owner>/<name>@<n>
t bundled: meadow, paper; from the Gallery as <owner>/<name>@<n>
p bundled: expense-claim, onboarding, shift-request, shift-roster, sign-off; from the Gallery as <owner>/<name>@<n>

A new system almost always writes r and v in place. s is the state's data: an object with one value per field of the rules' state.schema. Give it when the people, items or steps of this one instance are not in the rules (they usually should not be: see State).

A whole paneset

A loan register for the office's laptops. It opens as it is: copy it and change it.

{
  "$schema": "rulpane/paneset/v1",
  "r": {
    "$schema": "rulealize/ruleset/v1",
    "id": "laptop-loans",
    "version": "1.0.0",
    "requires": [
      { "plugin": "Rulealize.Plugin.TypeSchema", "version": "^1.3" },
      { "plugin": "Rulealize.Plugin.State", "version": "^1.0" },
      { "plugin": "Rulealize.Plugin.Sequence", "version": "^1.4" },
      { "plugin": "Rulealize.Plugin.Record", "version": "^1.0" },
      { "plugin": "Rulealize.Plugin.Comparison", "version": "^1.0" },
      { "plugin": "Rulealize.Plugin.Logic", "version": "^1.0" },
      { "plugin": "Rulealize.Plugin.Binding", "version": "^1.0" },
      { "plugin": "Rulealize.Plugin.Definition", "version": "^1.0" }
    ],
    "state": {
      "schema": {
        "laptops": { "op": "type.list", "element": { "op": "type.string", "minLength": 1 } },
        "loans": {
          "op": "type.list",
          "element": {
            "op": "rec.of",
            "fields": {
              "laptop": { "op": "type.string", "minLength": 1 },
              "who": { "op": "type.string", "minLength": 1, "maxLength": 40 }
            }
          }
        }
      },
      "initial": { "laptops": ["lt-01", "lt-02", "lt-03"], "loans": [] }
    },
    "definitions": {
      "out": {
        "op": "seq.select", "source": "$loans", "as": "l",
        "select": { "op": "rec.at", "record": "@l", "key": "laptop" }
      },
      "available": {
        "op": "seq.where", "source": "$laptops", "as": "x",
        "predicate": {
          "op": "logic.not",
          "value": { "op": "seq.any", "source": "#out", "as": "o", "predicate": { "op": "cmp.eq", "left": "@o", "right": "@x" } }
        }
      }
    },
    "inputs": {
      "lend": {
        "params": {
          "laptop": { "domain": "#available" },
          "who": { "open": { "op": "type.string", "minLength": 1, "maxLength": 40 } }
        },
        "effects": [
          {
            "op": "state.set", "path": "loans",
            "value": { "op": "seq.concat", "of": ["$loans", { "op": "seq.of", "of": [{ "laptop": "@laptop", "who": "@who" }] }] }
          }
        ]
      },
      "giveBack": {
        "params": { "laptop": { "domain": "#out" } },
        "effects": [
          {
            "op": "state.set", "path": "loans",
            "value": {
              "op": "seq.where", "source": "$loans", "as": "l",
              "predicate": { "op": "cmp.ne", "left": { "op": "rec.at", "record": "@l", "key": "laptop" }, "right": "@laptop" }
            }
          }
        ]
      }
    },
    "projections": {
      "available": "#available",
      "loans": "$loans",
      "counts": {
        "free": { "op": "seq.count", "source": "#available" },
        "out": { "op": "seq.count", "source": "$loans" }
      }
    }
  },
  "v": {
    "$schema": "rulealize/view/v1",
    "title": "Laptop loans",
    "layout": [
      { "c": "stats", "items": [ { "label": "Free", "bind": "counts.free" }, { "label": "On loan", "bind": "counts.out" } ] },
      { "c": "table", "title": "On loan", "bind": "loans", "columns": [ { "key": "laptop", "label": "Laptop" }, { "key": "who", "label": "Borrower" } ] },
      { "c": "actions", "title": "Lend one", "inputs": ["lend"], "as": "select" },
      { "c": "actions", "title": "Take one back", "inputs": ["giveBack"] },
      { "c": "list", "title": "Free now", "bind": "available" }
    ],
    "names": {
      "inputs": { "lend": "Lend", "giveBack": "Take back" },
      "params": { "laptop": "Laptop", "who": "Borrower" }
    }
  }
}

The forms used most

Every key below is exact; see Operations for the rest. Keys differ between operations that look alike — logic.and takes all, logic.or takes any, math.add takes of — so copy them from here rather than guessing.

{ "op": "cmp.eq", "left": "$stage", "right": "draft" }            // also cmp.ne, cmp.lt, cmp.lte, cmp.gt, cmp.gte
{ "op": "logic.and", "all": [ <expr>, <expr> ] }
{ "op": "logic.or", "any": [ <expr>, <expr> ] }
{ "op": "logic.not", "value": <expr> }
{ "op": "branch.if", "cond": <expr>, "then": <expr>, "else": <expr> }
{ "op": "math.add", "of": [ "$n", 1 ] }                            // math.sub takes left and right
{ "op": "seq.of", "of": [ "a", "b" ] }                             // a list, where an expression goes
{ "op": "seq.where", "source": "$items", "as": "i", "predicate": <expr reading "@i"> }
{ "op": "seq.select", "source": "$items", "as": "i", "select": <expr reading "@i"> }
{ "op": "seq.any", "source": "$items", "as": "i", "predicate": <expr reading "@i"> }
{ "op": "seq.count", "source": "$items", "as": "i", "where": <expr reading "@i"> }
{ "op": "seq.concat", "of": [ "$items", { "op": "seq.of", "of": [ { "id": "@id" } ] } ] }
{ "op": "rec.at", "record": "@i", "key": "status" }
{ "op": "rec.with", "record": "@i", "key": "status", "value": "done" }
{ "op": "state.set", "path": "stage", "value": "review" }           // an effect

Rules

The rules are a Rulealize rule set: a JSON document that says what a position looks like, what may be done to one, and when there is nothing left to do. The screen asks it three things — what can be done now, where a step leads, and whether it is over — and computes nothing itself.

The top-level keys

These and no others; a misspelt key is refused, not ignored.

Key What it is
$schema "rulealize/ruleset/v1" optional label
id, version a name, and a version x.y.z required
requires every plugin the document uses, as { "plugin": "<id>", "version": "^<x.y>" } required in practice
state schema (the fields and their types) and initial (one value per field) required
inputs the named things that may be done required
definitions expressions given a name, written once and used as #name optional
projections named values the screen shows, computed from the state optional
terminal when it is over, and the result to call the ending optional
uses, held rule sets this one is made of optional, rarely needed

Nodes and shorthands

Everything below those keys is a value or a node: an object with an op, such as { "op": "cmp.eq", "left": "$stage", "right": "draft" }. The part of op before the dot names the plugin it comes from, and that plugin must be in requires. Wherever a value goes, a node may go instead. An object without an op is a record whose values are evaluated, so { "laptop": "@laptop", "who": "@who" } builds a record. A JSON array is not a list where an expression goes: write { "op": "seq.of", "of": [ … ] }.

Written Means Needs
"$total" the state field total Rulealize.Plugin.State
"@n" the parameter n, or a name bound by as Rulealize.Plugin.Binding
"#open" the definition open Rulealize.Plugin.Definition

Text that has to start with $, @ or # is written { "op": "literal", "value": "#1" }.

Every operation is one of four kinds, and the kind decides where it may be written:

Kind Does Goes in
expression computes a value when, domain, effect values, projections, terminal, definitions
effect writes to the state only in an input's effects
schema declares a type state.schema, and a parameter's open
draw picks at random, in the browser only inside effects

State

"state": {
  "schema":  { "stage": { "op": "type.enum", "values": ["draft", "review", "done"] } },
  "initial": { "stage": "draft" }
}

Every field has a type, from a schema operation (type.*, rec.of, rec.map, …). Ask of each field whether it is a rule or this instance: the people, items, steps and amounts of one case belong in the state (initial, or the paneset's s), so that one rule set serves every case. Lists of them are type.list with an element type, and a list of records is type.list of rec.of.

Inputs

"inputs": {
  "reject": {
    "params":   { "reason": { "domain": { "op": "seq.of", "of": ["scope", "cost"] } } },
    "actor":    "reviewer",
    "when":     { "op": "cmp.eq", "left": "$stage", "right": "review" },
    "validate": [ { "require": <expression:Boolean>, "code": "reason.missing" } ],
    "effects":  [ { "op": "state.set", "path": "stage", "value": "rejected" },
                  { "op": "state.set", "path": "reason", "value": "@reason" } ]
  }
}
  • effects (required) — what it does, in order. An input's name may not contain ..
  • params — each parameter has exactly one of:
    • domain: an expression giving the list of values it may take. Each value is a separate step on the screen, a button or an entry in a list to pick from.
    • open: a schema node, for a value somebody types — a name, an amount, a date as text. The screen shows a form field, held to the schema. { "field": "name" } takes the schema of the state field name. An open parameter may be read in effects and validate, never in when, actor or a domain.
  • when — whether the input is allowed now. Left out, it always is.
  • validate — checked when an open value arrives; each clause's code is the refusal shown under the field when require is false. Every clause must read an open parameter; a condition on the state or on a domain parameter alone is refused here and belongs in when (which may read domain parameters, so "only a free slot" is when, not validate).
  • actor — a label for whose step this is. The screen groups steps by it. Nobody signs in: anybody holding the link can take any step; the label only says whose it is meant to be.

Definitions, projections and the end

"definitions": {
  "open":  { "op": "seq.where", "source": "$steps", "as": "s", "predicate": … },
  "owner": { "params": ["id"], "body": { "op": "rec.at", "record": "$owners", "key": "@id" } }
},
"projections": { "summary": { "stage": "$stage", "left": { "op": "seq.count", "source": "#open" } } },
"terminal":    { "when": { "op": "cmp.eq", "left": "$stage", "right": "done" }, "result": "$stage" }

A definition is read as #name; one with params is called with { "op": "def.call", "def": "owner", "args": { "id": "@who" } }. Definitions may not call themselves. Projections are what a view binds to, and any shape: a value, a list, a record. When terminal.when is true the screen shows the result and offers nothing more — though steps whose when still holds are still listed by the rules, so write when to stop them.

Values and null

Values are null, booleans, numbers (no integer/fraction split), text, lists, records and a plugin's own values (a grid coordinate). Values of different kinds are never equal: 1 is not "1". A lookup that finds nothing gives null — past the end of a list, a missing key, off a board — and null equals only null; ordering or arithmetic on null is an error. Rules lean on that: no bounds check is needed before rec.at or seq.elementAt.

Operations

Every operation Rulpane can run. <expr> is any expression; <expr:Number> one giving a number; <schema> a schema node; <state field> a field written "$name".

Kind: Expr expression, Effect, Schema, Draw (an expression allowed only inside an input's effects). "k"?: marks an optional key.

The view

Without v, the screen is made from the rules: their projections (or the state), every step as a button grouped by actor and input, a form for open parameters, and the result at the end. A view lays it out instead.

{
  "$schema": "rulealize/view/v1",
  "title": "Expense claim",
  "layout": [ /* blocks, top to bottom */ ],
  "names": { "inputs": { … }, "params": { … }, "codes": { … }, "values": { … } }
}

A binding (bind) is a projection name followed by .-separated steps into it (summary.stage), or a state field as the rules write one ($total); a number steps into a list. A path that leads nowhere shows —; a first name the rules do not have is refused.

Block Keys Shows
heading text a heading
text text a paragraph
fields title?, rows: [{ label, bind, tone?, showWhen? }] a card of label–value rows. tone maps a value to neutral, accent, ok, warn or danger, shown as a coloured chip
stats items: [{ label, bind }] values set large, side by side
list title?, bind a list's values side by side
table title?, bind, columns?: [key or { key, label }] a list of records, one per row; every key without columns
board title?, bind, play?, pieces? a Grid board in a state field ($board); play is "input.param" to make squares buttons; pieces maps values to dark, light, accent, ok, warn, danger
actions title?, inputs, as? the steps of the listed inputs, or "*" for every step; "as": "select" shows an input's choices as one list and a button. A block with nothing to offer now is hidden

Every block, and every fields row, takes showWhen: a binding that must read true for it to show. The view holds no conditions of its own; a projection says when.

names says what the screen calls the rules' own names, in the one language the view is written in: inputs (step buttons), params (argument and field names), codes (refusals), values (any value shown). A name left out is shown as the rules spell it. title replaces the rule set's id in the heading.

A view meant for many rule sets declares expects — the projections it reads, with types, and the inputs it names — and binds nothing else; the bundled stages and progress are such views. b in the paneset then says where rules that call those things something else keep them: "b": { "all": "$steps", "done": "$done", "place": "game.place" }.

The theme

{
  "$schema": "rulealize/theme/v1",
  "colors": { "light": { "accent": "#1f7a4d", "accent-soft": "#e4f4ea" }, "dark": { "accent": "#6fd6a0" } },
  "radius": "round",
  "font": "rounded",
  "density": "compact"
}

colors.light and colors.dark take any of bg, surface, sunken, text, muted, line, line-strong, accent, accent-hover, accent-text, accent-soft, mark, mark-text, ok, ok-soft, danger, danger-soft, warn, warn-soft, as #rrggbb. radius is sharp, default or round; font is inter, system, serif or rounded; density is comfortable or compact. Every pair of colours text is set in must reach a contrast of 4.5:1, or the theme is refused with the pair that failed. The top bar keeps Rulpane's own look.

What a link cannot do

  • Keep anything secret, or know who is who. The whole state is in the link, and nobody signs in: anybody with the link sees everything and can take any step. Fine for a team's own hand-overs; not for votes, payments or anything to hide.
  • Be in two places at once. Each step makes a new link. Two people working from the same link make two separate histories; send the link on, one person at a time.
  • Run code, load anything from elsewhere, or ask for passwords. A link holds documents, not HTML or script; text in a view is shown as text. The top bar always says who made the screen.
  • Use plugins other than those above, or more than a bounded amount of work per step.

Before you answer

  • The paneset, and v and t when written in place, each have their $schema.
  • Every op is in Operations, with only the keys its form shows.
  • Every plugin whose op, $, @ or # is used is in requires.
  • Lists where an expression goes are seq.of, not JSON arrays (arrays are fine in state.initial, s and a view).
  • No open parameter is read in when, actor or a domain; every validate clause reads one.
  • Every view binding names a projection the rules have (or a state field as $name).
  • The link is one line, and every space in it is %20.

When it does not open

The page shows why, with the path to the node at fault, for instance:

/inputs/go/effects[0]/value: 'math.add' comes from Rulealize.Plugin.Arithmetic, which this rule set does not name in 'requires'.
/inputs/go/effects[0]/value: an array is not an expression. Sequences are produced by operations, never written down.
/state/schema: must declare at least one field.

The usual causes:

  • an operation that is not in Operations, or a key that is not in its form;
  • a plugin used but missing from requires;
  • a list written as a JSON array where an expression goes, instead of seq.of;
  • an open parameter read in when or a domain, or a validate clause that reads none;
  • a paneset, view or theme without its $schema;
  • a view binding a projection the rules do not have, or a key a table's records do not have;
  • the link cut at a space: write spaces as %20.
